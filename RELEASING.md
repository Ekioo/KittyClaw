# Releasing KittyClaw

Versions flow from git tags via MinVer — never edit a csproj version. The
CHANGELOG entry is the single source of the release notes: the GitHub release
body is generated from it.

## Ritual

1. **Changelog** — on `dev`, add a `## [vX.Y] — YYYY-MM-DD` entry at the top of
   `CHANGELOG.md`: a one-line summary, then `### Highlights` prose, then
   `### Added` / `### Changed` / `### Fixed` (and `### Security` when relevant),
   ending with a `---` separator. The one-line summary doubles as the release
   title. Changelog headings intentionally use the short `vX.Y` release line;
   the corresponding MinVer tag includes the patch component (for example,
   heading `v0.13` maps to tag `v0.13.0`). Commit and push.
2. **Merge** — merge `dev` into `main` and push.
3. **Tag** — on `main`:
   ```
   git tag v0.13.0 && git push origin v0.13.0
   ```
4. **Release** — still on `main`:
   ```
   pwsh tools/publish-release.ps1
   ```
   Run this on Windows with the .NET 10 SDK and authenticated GitHub CLI.
   This builds the self-contained Windows x64 Velopack installer and the release zip (Web + QaRunner at the root, ClaudeMock in
   `qa-mock/` — the layout `publish-stable.ps1` uses), verifies the MinVer
   version matches the tag, creates the GitHub release from the CHANGELOG entry,
   and uploads `KittyClaw-v0.13.0.zip` (substituting the version being released),
   `Ekioo.KittyClaw-win-Setup.exe`, the full `.nupkg`, `releases.win.json`, and `RELEASES`.
   New releases are created as drafts and published only after all assets upload.
   Pass `-KeepDraft` to retain the uploaded release as a draft while checking the
   installer and delta package. Publish the verified draft with
   `gh release edit vX.Y.Z --draft=false --latest`.
   Keep the package and feed attached to the same release: installed clients use
   Velopack's GitHub source, while source installations use the legacy release link.
   Before packaging, `Get-WindowsReleaseBaseline.ps1` downloads the newest older stable
   Windows full package. Velopack uses it to generate the new `*-delta.nupkg`, which is
   uploaded alongside the full package. The first Velopack release has no baseline and
   uses full downloads. API/download failures abort publication rather than silently
   disabling incremental updates. Existing/future tags and prereleases are excluded
   when selecting the baseline. Each release feed lists only that release's assets;
   previous releases retain the earlier packages used to build an update chain.
   Publishing the release is what triggers
   the in-app update banner: running instances poll `releases/latest`.
5. **Local stable instance** (optional) — republish `C:\KittyClaw-stable` with
   `pwsh tools/publish-stable.ps1`, or unzip the release asset there, then
   start `KittyClaw.Web.exe` (defaults to http://localhost:5230).

Afterwards, switch back to `dev` for further work.

## Local installer build

```powershell
pwsh tools/build-windows-installer.ps1 -Version 0.19.0-test.1
```

This does not publish anything. Outputs are under `publish-windows/<version>/`.
The pinned local `vpk` tool is restored from `dotnet-tools.json`; its version must match
the `Velopack` PackageReference. The installer embeds the runtimes and requires no
external .NET bootstrap dependency. A portable ZIP is also generated by Velopack,
but only the installer and update feed are included in the release upload.

`-SignTemplate` can pass a configured signing command to Velopack on either script;
`publish-release.ps1` also accepts it through `KITTYCLAW_SIGN_TEMPLATE`.
Unsigned local artifacts are suitable for testing; production signing credentials must
be provided by the release environment. Runtime security fixes ship through a new
self-contained KittyClaw release.

Verify local artifacts without touching the running main instance:

```powershell
pwsh tools/Test-WindowsInstaller.ps1 -ArtifactsDir publish-windows/0.19.0-test.1
```

This launches the payload on port 5232 with a fresh registry, disabled providers, and
external .NET lookup disabled, checks the home page and static files, then verifies
the actual update feed and package through Velopack's test locator. It does not
install the application or restart an existing instance. Close any other debug
instance on port 5232 first, or pass another isolated `-Port`.

Verify an incremental update between two local builds made in the same output directory:

```powershell
pwsh tools/Test-WindowsDeltaUpdate.ps1 -ArtifactsDir publish-windows/test-feed -BaselineVersion 0.19.0-test.1 -TargetVersion 0.19.0-test.2
```

The test source contains only the delta, not the target full package. It must reconstruct
and validate the target from the previous cached full package; a full-download fallback
cannot make the test pass. CI builds two versions and runs this check automatically.
